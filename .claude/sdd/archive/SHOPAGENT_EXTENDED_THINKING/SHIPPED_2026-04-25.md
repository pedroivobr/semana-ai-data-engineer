## Summary

Adicionado extended thinking da API Anthropic ao ShopAgent Day 3: o raciocínio interno do Claude agora aparece em tempo real no Chainlit como um `cl.Step("🧠 Pensamento")` streamado, com toggle on/off via `cl.ChatSettings`, contador de tokens e custo estimado por query, e persistência assíncrona dos blocos de thinking no Qdrant (`shopagent_thinking`). A implementação foi cirúrgica — 4 arquivos modificados, nenhum componente existente quebrado — e o bug de incompatibilidade entre o modelo de embeddings do ingest (`all-MiniLM-L6-v2` / `fast-all-minilm-l6-v2`) e o `tools.py` também foi corrigido durante o processo.

## Lessons Learned

### Process

- O workflow Brainstorm → Define → Design → Build funcionou bem para uma feature de complexidade média — as perguntas do brainstorm evitaram uma decisão errada (AgentExecutor vs LangGraph)
- A etapa de YAGNI foi subvertida pelo usuário (todas as features mantidas) — em projetos pedagógicos, o usuário frequentemente quer o escopo completo para demonstração

### Technical

- **`temperature=1` é obrigatório para extended thinking** — não documentado de forma proeminente, descoberto ao testar; merece destaque em futuras implementações
- **`qdrant_client >= 1.12` removeu `search()`** — o método correto é `query_points(collection_name, query=vector, using=VECTOR_NAME)`. Sempre verificar a versão do cliente antes de usar métodos de busca
- **Mismatch de embedding model entre ingest e query é silencioso** — o Qdrant retorna erro de vector name, não de dimensão. Padronizar `EMBED_MODEL` e `VECTOR_NAME` como constantes compartilhadas previne isso
- **`asyncio.create_task` em handlers Chainlit** — funciona bem para operações best-effort; o event loop do Chainlit processa a task após o `await msg.send()`
- **Hot-reload do Chainlit não é confiável** — ao alterar `tools.py` com o servidor rodando, reiniciar explicitamente é mais seguro

### Communication

- A pergunta "o que você quer dizer com thinking visualization?" salvou tempo — havia 3 interpretações possíveis (extended thinking real, visualização de steps ReAct, spinner simples)
- Perguntar sobre `budget_tokens` antes do design revelou o requisito pedagógico de configurabilidade

### Tools & Libraries

- `fastembed.TextEmbedding` direto é mais simples que `llama_index.embeddings.fastembed.FastEmbedEmbedding` para buscas que não precisam do índice LlamaIndex — menos camadas de abstração
- `cl.ChatSettings` + `cl.input_widget.Switch` funciona exatamente como documentado para toggles em tempo real
- `asyncio.to_thread` para embeddings sincrônicos dentro de handlers async é o padrão correto
